# اتصال Supabase از دامنهٔ خود سایت

## وضعیت

پیاده‌سازی محلی برای مسیر اول مورد تأیید کاربر است. دیتابیس جابه‌جا نشده، SQL یا تنظیمات پروژه تغییر نکرده و لیارا روشن/منتشر نشده است. تا انتشار و آزمون روی شبکهٔ دارای مشکل، رفع مشکل اینترنت ایران قطعی اعلام نمی‌شود.

## مسیر درخواست

مرورگر → `/api/supabase` روی دامنهٔ سایت → پروژهٔ Supabase مشخص‌شده.

فقط HTTP مورد استفادهٔ فعلی برای ورود با رمز/پیامک، refresh/logout، داده و RPCهای عمومی با مجوز خود کاربر، بارگذاری/حذف عکس و دریافت عکس عمومی یا لینک امضاشده عبور می‌کند. مرورگر از همان کلید عمومی و JWT کاربر استفاده می‌کند؛ هیچ service-role به این مسیر اضافه نمی‌شود. کلاینت‌های خصوصی سرور و کنترل RLS موجود تغییر نکرده‌اند.

URL اصلی پروژه در SDK حفظ شده و فقط transport درخواست‌ها تغییر می‌کند؛ نام کلید نشست، namespace سبد و دفترهای بازیابی تغییر نکرده‌اند. آدرس عکس‌های قدیمی در دیتابیس بازنویسی نشده؛ فقط هنگام نمایش و بازکردن عکس به مسیر داخلی تبدیل می‌شود. آدرس‌های مربوط به پروژه‌های دیگر دست‌کاری نمی‌شوند. عکس‌های JPG/PNG/WebP/GIF/AVIF مجازند؛ HTML/SVG موفق از این مسیر هم‌مبدأ ارائه نمی‌شود.

## مرزها

- مقصد فقط دو پروژهٔ شناخته‌شدهٔ اصلی و تست با HTTPS معتبر است؛ مسیر باز برای URL دلخواه نیست.
- مسیرهای مدیریتی Auth، schema خصوصی و سرویس‌های نامرتبط مسدودند؛ redirect دنبال نمی‌شود.
- فقط headerهای لازم از کلاینت کپی می‌شوند؛ Cookie، زنجیرهٔ forwarding و کلیدهای خصوصی اضافه نمی‌شوند. Set-Cookie و CORS عمومی upstream به مرورگر کپی نمی‌شوند.
- Origin خارجی و درخواست cross-site رد می‌شود. پاسخ‌های Auth/Data، خطاها، عکس‌های امضاشده/مرجوعی و درخواست‌های دارای هویت no-store هستند. تنها عکس عمومی محصول با پاسخ ۲۰۰، بدون query، Authorization یا Range تا ۵ دقیقه کش مرورگر/CDN می‌شود. پاسخ‌ها nosniff و CSP محدود دارند؛ بدنه، رمز، JWT و لینک امضاشده در برنامه log نمی‌شوند.
- سقف بدنه ۶ MiB، سقف پاسخ ۳۲ MiB است. ظرفیت Auth/Data/آپلود حداکثر ۸ درخواست، و خواندن عکس در ظرفیت مستقل ۴ درخواست است؛ حداکثر ۶۴ عکس تا ۱۰ ثانیه در صف می‌مانند و صف پُر/منقضی پاسخ ۵۰۳ می‌دهد. این جداسازی مانع مصرف ظرفیت پروفایل توسط گالری می‌شود. زمان شبکه/بدنه محدود است. محدودکنندهٔ عمومی ۳۰۰ و نوشتن Auth بیست درخواست در دقیقه برای IP مشاهده‌شدهٔ سرور است. این محدودکننده محلی به پردازش و وابسته به تنظیم trust proxy فعلی است؛ معادل کنترل توزیع‌شده یا ممیزی تازهٔ مسیر واقعی IP نیست.
- خطا/timeout به خطای محدود تبدیل می‌شود؛ fallback خودکار به اتصال مستقیم مرورگر وجود ندارد. اطلاعات هویتی کاربر توسط Supabase اعتبارسنجی می‌شود.
- Realtime/WebSocket، OAuth redirect و Edge Functions مرورگر در کد فعلی استفاده نمی‌شوند و این بسته پشتیبانی آن‌ها را ادعا نمی‌کند. برای اضافه‌کردنشان مسیر جدا و بررسی لازم است.

## اجرا

در حالت توسعهٔ معمولی، Vite مسیر را در همان سرور محلی فراهم می‌کند؛ برای خود این relay بک‌اند جدا روی پورت ۳۰۰۱ لازم نیست. APIهای قبلی پرداخت/ERP همچنان تنظیمات خودشان را دارند. حالت local-test به همین پروژهٔ تست و محدودیت‌های پیشین خود متکی می‌ماند و relay عمومی در آن نصب نمی‌شود.

در انتشار Node، `SUPABASE_URL` موجود، مقصد سرور را مشخص می‌کند؛ باید پروژهٔ اصلیِ متناظر با تنظیم عمومی کلاینت باشد. `VITE_SUPABASE_URL` را به دامنهٔ سایت یا مسیر proxy عوض نکنید؛ شناسهٔ پروژه باید حفظ شود. متغیر تازه یا تغییر DNS لازم نیست. کد سرور و مرورگر باید با هم منتشر شوند؛ انتشار فقط frontend باعث 404/SPA به‌جای API می‌شود.

سرور لیارا باید خودش اتصال پایدار به Auth/Data/Storage داشته باشد. این روش اختلال مسیر خروجی سرور یا قطعی Supabase را رفع نمی‌کند. سهمیه‌های Auth/Storage و اثر تجمیع ترافیک در IP خروجی سرور باید در پذیرش زنده/بار بررسی شوند؛ header جعلی IP از مرورگر به سرویس فرستاده نمی‌شود.

پس از روشن‌شدن و انتشار نسخهٔ هماهنگ، دستور زیر را در پوشهٔ محلی پروژه روی کامپیوتر اجرا کنید:

```
node scripts/check-supabase-relay.mjs
```

این بررسی فقط health عمومی و یک خواندن محدود کاتالوگ را انجام می‌دهد؛ رمز/ورود/SMS/پرداخت یا دادهٔ شخصی چاپ نمی‌کند. سپس مالک باید ورود/تمدید نشست، کاتالوگ و عکس قدیمی/امضاشده را روی شبکهٔ دارای مشکل، بدون VPN، تأیید کند. اگر proxy در لیارا موفق ولی کاربر هنوز خطا داشت، آن خطا باید جدا تشخیص داده شود؛ فیلترینگ قطعی یک طرف از شواهد قبلی اثبات نشده است.

بستهٔ فعلی بدون commit/push/merge/deploy آماده شده است؛ نصب/فعال‌سازی Migrationهای فاز۵ مسیر مستقلی دارد و این تغییر گیت‌های آن‌ها را باز نمی‌کند.

مبنای طراحی: [custom fetch رسمی Supabase](https://supabase.com/docs/reference/javascript/initializing)، [پایداری نشست در Auth](https://supabase.com/docs/reference/javascript/auth).
