# SEO فنی، بستهٔ محلی فاز ۶ — ۲۷ اکتبر ۲۰۲۶

## تغییرات
- مسیرهای عمومی تعریف مشخص دارند؛ canonical و og:url فقط دامنهٔ اصلی HTTPS و مسیر معتبر را می‌گیرند. query و fragment وارد این اطلاعات نمی‌شوند.
- فیلترهای فروشگاه canonical مشترک /shop دارند و در sitemap جداگانه ثبت نمی‌شوند. ساخت صفحات دسته‌بندی قابل نمایه‌شدن با محتوای مستقل، کار جداگانه است.
- حساب، مدیریت، ورود، سبد، پرداخت، رهگیری سفارش و مسیر ناشناخته در متادیتای رندرشده noindex هستند و canonical یا og:url خصوصی ندارند. این علامت جایگزین احراز هویت نیست.
- عنوان و توضیح پیش‌فرض برای صفحات عمومی، حتی هنگام بارگذاری، تعریف شده است. عنوان و توضیح اختصاصی صفحات موجود حفظ شده‌اند. نشان تأیید گوگل و اینماد حفظ شده‌اند؛ نام کاربری ساختگی Lovable و تصویر خالی حذف شده‌اند.
- Product JSON-LD از قیمت ریالی و همان وضعیت موجود/ناموجود نمایش‌داده‌شده در صفحه ساخته می‌شود. موجودی واقعی انبار دوباره محاسبه نمی‌شود. امتیاز، نظر، تخفیف یا وعدهٔ ارسال ساختگی اضافه نشده است.
- نشانه‌های HTML در متن JSON-LD escape می‌شوند؛ تصویر placeholder، URL امضاشده، query یا credential در متادیتای تصویر قرار نمی‌گیرد. تصویر عمومی نسبی به آدرس کامل تبدیل می‌شود.
- sitemap از محصولات فعال با ترتیب ثابت id و صفحه‌های ۵۰۰تایی خوانده می‌شود؛ سقف محافظتی این پیاده‌سازی ۱۰هزار محصول است. خطا، slug نامعتبر یا عبور از سقف، ساخت را ناموفق می‌کند. نوشتن فایل پس از کامل‌شدن خواندن و با فایل موقت و rename انجام می‌شود؛ فایل قبلی با نتیجهٔ ناقص جایگزین نمی‌شود.
- robots برای همهٔ ربات‌ها یک سیاست دارد؛ مسیرهای API از crawl خارج شده‌اند. مسیر خصوصی صرفاً برای خواندن noindex با robots مسدود نشده است.

## شواهد
- تمام ۱۵۸۳ آزمون واحد/یکپارچه موفق؛ ۴۱ مورد جدید مربوط به سیاست SEO و sitemap است.
- ۶ سناریوی مرورگر موفق: ورود، پرداخت با quote، رسید جعلی، canonical و حذف schema بعد از خروج، metadata حساب، محصول ناموجود و جلوگیری از تزریق script.
- بررسی TypeScript و lint فایل‌های تغییرکرده موفق؛ build ایزوله موفق، هشدار قبلی حجم bundle حدود ۹۱۷ کیلوبایت هنوز باقی است.
- اجرای واقعی سازندهٔ sitemap فقط‌خواندنی بود و ۷۹ آدرس از صفحات عمومی و کاتالوگ فعلی تولید کرد. هیچ داده‌ای در دیتابیس تغییر نکرد.

## محدودیت‌ها و کارهای بعد از انتشار
- این سایت SPA است؛ اطلاعات اختصاصی محصول و noindex مسیرها پس از اجرای JavaScript ایجاد می‌شوند. پیش‌رندر/SSR یا metadata اختصاصی در پاسخ HTML اولیه در این بسته پیاده نشده است؛ بعضی ربات‌های شبکه‌های اجتماعی ممکن است فقط اطلاعات عمومی اولیه را ببینند.
- تأیید Rich Results، URL Inspection و ارسال sitemap در Search Console پس از انتشار انجام می‌شود. نتیجهٔ رتبه، ایندکس یا نمایش غنی تضمین نشده است.
- snapshot تراکنشی از کاتالوگ گرفته نمی‌شود؛ اگر هم‌زمان محصولات در حال تغییر باشند، sitemap اجرای بعدی باید دوباره ساخته شود. این ابزار پایش پیوستهٔ تغییر محصول نیست.
- build عادی اکنون هنگام دسترس‌نبودن کاتالوگ متوقف می‌شود؛ این رفتار عمداً مانع انتشار sitemap ناقص است. build ایزوله اتصال زنده ندارد و برای تأیید sitemap انتشار کافی نیست.
- فایل public/sitemap.xml تولیدی است؛ در Git نادیده گرفته می‌شود و build عادی آن را می‌سازد.
- انتشار، commit/push، فعال‌سازی مانیتور زمان‌بندی‌شده و تنظیمات به‌تعویق‌افتادهٔ فاز ۵ انجام نشده‌اند. کل فاز ۶ تکمیل اعلام نمی‌شود.

## منابع طراحی
سیاست canonical و هماهنگی sitemap بر پایهٔ [راهنمای رسمی گوگل](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) است. اطلاعات محصول با [راهنمای Product گوگل](https://developers.google.com/search/docs/appearance/structured-data/product-snippet) تطبیق داده شد. صفحه‌بندی مطابق [range در مستندات Supabase](https://supabase.com/docs/reference/javascript/range)، همراه ترتیب ثابت انجام می‌شود.
