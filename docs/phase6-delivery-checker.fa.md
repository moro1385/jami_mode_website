# پذیرش کش پس از انتشار — فاز ۶، ۳۰ اکتبر ۲۰۲۶

## اجرا

در پوشهٔ پروژه، با Node نصب‌شده:

```sh
node scripts/check-site-delivery.mjs
```

پیش‌فرض دامنهٔ اصلی است. فقط دامنهٔ اصلی، www و مقصدهای محلیِ مجاز ابزار سلامت پذیرفته می‌شوند. هیچ متغیر محیطی، رمز، نشست کاربر یا کلید مدیریتی لازم نیست. خروجی JSON و کد خروج ۰ برای `ok`، ۱ برای شکست بررسی یا دسترس‌ناپذیری، و ۲ برای ورودی نامعتبر است.

## معیارها

- خانه و پوستهٔ حساب: HTML با `no-store`، بدون شاهد کش مشترک؛ حساب باید `X-Robots-Tag: noindex` داشته باشد. این درخواست احراز هویت ندارد و محتوای حساب واقعی را بررسی نمی‌کند.
- robots.txt: پاسخ ۲۰۰ متنی با `max-age=0, must-revalidate`.
- فایل ساخته‌شدهٔ ناموجود: ۴۰۴ و `no-store`؛ برگشت HTML با کد ۲۰۰ پذیرفته نیست.
- ورودی JavaScript و CSS استخراج‌شده از HTML جاری: نام hashدار، همان دامنه، پاسخ صحیح، `public, max-age>=31536000, immutable` و بدون Set-Cookie.

حداکثر شش درخواست ترتیبی GET انجام می‌شود؛ هر درخواست ده ثانیه مهلت دارد. HTML حداکثر ۲۵۶ کیبی‌بایت خوانده می‌شود؛ بدنهٔ فایل‌های دیگر دانلود کامل نمی‌شود. redirect دنبال نمی‌شود. مرجع خارجی، query، fragment، مسیر نامعتبر یا چند ورودی مبهم رد می‌شود. خروجی شامل HTML، کوکی، شناسه مشتری، URL ورودی فایل یا متن خام خطای شبکه نیست.

## حدود نتیجه

`ok` سیاست هدر و شکل پاسخ همین نمونه‌ها را تأیید می‌کند. درخواست‌ها برای دریافت پاسخ تازه فرستاده می‌شوند؛ این ابزار سنجش hit ratio، بار، زمان دانلود تصویر، Core Web Vitals یا مجوزهای حساب نیست. Vite در ساخت فعلی یک ورودی module و یک stylesheet دارد؛ تغییر این قرارداد نیازمند تغییر آگاهانهٔ ابزار است.

`unavailable` یعنی هیچ پاسخ HTTP قابل بررسی دریافت نشده؛ خرابی خود سایت از آن نتیجه گرفته نمی‌شود. `needs_review` یعنی دست‌کم یک پاسخ دریافت شده ولی همه معیارها برقرار نبوده‌اند. وضعیت هر بررسی به‌طور جداگانه گزارش می‌شود؛ نتیجهٔ موفق محلی جای پذیرش لیارا/Cloudflare را نمی‌گیرد.

## اعتبارسنجی محلی

آزمون‌ها پاسخ موفق، هدر خصوصی کش‌پذیر، override لبه، Age و HIT، جلوگیری از مقصد بیرونی، فایل ناموجود، ورودی بزرگ و عدم چاپ داده خام را بررسی می‌کنند. یک آزمون HTTP واقعی نیز همین ابزار را مقابل middleware تولید روی سرور موقت loopback اجرا می‌کند؛ هیچ اتصال به Supabase یا داده زنده ندارد. این آزمون‌ها با `npm test` در CI موجود هم اجرا می‌شوند.

این بسته فقط ابزار پذیرش و مستندات است؛ رفتار فروشگاه، تنظیم CDN، دیتابیس و پرداخت را تغییر نمی‌دهد. سنجش سرعت واقعی، پایش دائمی و بررسی تنظیمات حفاظت شاخه با موفقیت این ابزار انجام‌شده محسوب نمی‌شوند.
