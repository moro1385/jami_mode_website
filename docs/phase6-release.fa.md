## آخرین اصلاحات
ProductRail قبلاً سه hook را برای جدیدترین، ویژه و عمومی هم‌زمان فعال می‌کرد، هرچند فقط یک خروجی نمایش داده می‌شد. اکنون یک query مناسب نوع ردیف فعال می‌شود. مرورگر صفحهٔ اصلی دقیقاً دو خواندن محصول با limit=12، یکی is_new و دیگری is_featured، ثبت کرد. خطای مجوز همچنان خطا است و به فهرست خالی تبدیل نمی‌شود.

رسیدگی به فایل‌های ثابت از APIها جدا و بعد از آن‌ها نصب شده است. تنها نام‌های مطابق قرارداد hashدارِ پوشه assets کش immutable دارند. HTML برای مسیرهای مستقیم، از جمله حساب و نتیجهٔ پرداخت، no-store است. مسیر asset ناموجود پاسخ ۴۰۴ no-store می‌گیرد و به HTML با وضعیت ۲۰۰ تبدیل نمی‌شود؛ مرز خطای رابط می‌تواند شکست chunk را رسیدگی کند. فایل عمومی بدون hash با ETag و بازاعتبارسنجی عرضه می‌شود. این سیاست روی دادهٔ حساب، احراز هویت، پاسخ پرداخت یا APIهای محافظت‌شده کش عمومی ایجاد نمی‌کند.

هشدار qs مربوط به stringify با قالب comma و شکل ورودی خاص بود؛ آسیب‌پذیری قابل بهره‌برداری در برنامهٔ فعلی اثبات نشده است. نسخهٔ امن نصب و lockfile ثبت شد؛ هر دو بازتولید هشدار، با و بدون encodeValuesOnly، بدون exception عبور کردند. [جزئیات هشدار و نسخهٔ وصله‌شده](https://github.com/advisories/GHSA-6pq8-jhm2-2vcw).

## اعتبارسنجی این نسخه
- 1599 آزمون واحد/یکپارچه موفق، صفر شکست؛ شامل ۱۱ بررسی HTTP واقعی کش/HTML/API/ETag و ۵ بررسی query ردیف‌ها.
- تمام ۸۱ سناریوی مرورگر آفلاین موفق و بدون skip. این اجرا پیش از وصلهٔ qs بود؛ پس از وصله، تمام آزمون‌های واحد/سرور و build دوباره اجرا شدند. مسیر آفلاین مرورگر از سرور آزمایشی Node HTTP استفاده می‌کند.
- TypeScript و lint کل پروژه موفق. build ایزوله موفق؛ هشدار قبلی حجم bundle و توضیح annotation وابستگی zod همچنان وجود دارند و پنهان نشده‌اند.
- npm audit --package-lock-only پس از اصلاح: صفر info/low/moderate/high/critical در پاسخ فعلی رجیستری. فقط یک package نصب‌شده و یک بخش lockfile تغییر کرد؛ package.json تغییر نکرد.
- API زنده، SQL، درگاه و تنظیم Cloudflare برای این اصلاحات دست‌کاری نشدند. پشتیبان/بازیابی دیتابیس انجام نشده است. تست دیتابیس موقت قبلی دوباره اجرا نشد چون schema/SQL تغییر نکرد.

## چک‌لیست انتشار و پذیرش، هنوز اجرا نشده
1. بستهٔ تغییرات را با manifest همین گزارش تطبیق دهید؛ فایل‌های آرشیو شخصی، PDFهای مرجع، .env و supabase/.temp/cli-latest جزو این بسته نیستند. اجازهٔ انتشار عمومی این بسته و commit/merge/deploy باید در محدودهٔ درخواست انتشار مشخص باشد.
2. پس از انتشار همین نسخه، / و یک مسیر مستقیم محصول را با HTML تازه و یک فایل hashدار را با هدر cache مناسب بررسی کنید. یک asset ناموجود باید ۴۰۴ بدهد. Cloudflare نباید HTML یا API خصوصی را برخلاف هدر مبدأ کش کند.
3. ورود، نام پروفایل، تصویر محصول و انتخاب تصویر دوم، سبد و خطای شبکه را روی دامنه و اینترنت هدف بررسی کنید. بدون تأیید جداگانه پرداخت واقعی یا تغییر دادهٔ تولید انجام نشود.
4. بررسی سلامت live/maintenance/auth را از محیطی با اتصال معتبر اجرا کنید. ابزار تاریخچه در حال حاضر one-shot است؛ زمان‌بندی و مقصد هشدار هنوز نصب نشده‌اند. گزارش مصنوعی یا probe ناموفق از این نشست، شاهد سلامت/قطعی جهانی نیست.
5. برای SEO، sitemap تازهٔ build را باز و تعداد/آدرس‌ها را کنترل کنید؛ سپس Search Console، URL Inspection و Rich Results را روی دامنهٔ منتشرشده بررسی کنید. برای Web Vitals، محیط، viewport، شبکه، تعداد اجرا و LCP/CLS/INP ثبت شوند؛ از اندازهٔ bundle زمان سرعت حدس زده نشود.
6. موارد قبلیِ معوق فاز ۵ مستقل‌اند: ورود معتبر CLI لیارا، تطبیق source/runtime flags و تأیید gateها. هنوز اجازه‌ای برای عبور از این پیش‌نیازهای معوق برداشت نشده و gateها فعال نشده‌اند.
7. در صورت شکست انتشار کد، نسخهٔ سالم قبلیِ برنامه را از تاریخچهٔ میزبانی بازگردانید. rollback خودکار SQL، معکوس‌کردن migration یا پاک‌کردن داده جزو این برنامه نیست. سپس سلامت و مسیرهای کلیدی مجدداً بررسی شوند.
