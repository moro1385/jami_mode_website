# رفع مسدودشدن منابع عمومی کاتالوگ برای رندر گوگل

## شاهد و علت

در ۲۹ اکتبر ۲۰۲۶، گزارش Page indexing با تاریخ دادهٔ ۲۳ اکتبر، ۸۸ آدرس در گروه Discovered - currently not indexed نشان داد. بررسی زندهٔ یک محصول فعال، در همان روز HTTP 200 و دریافت موفق داشت، اما پس از رندر JavaScript با noindex و بدون canonical پایان یافت.

در View tested page ← More info ← Page resources، خود گوگل درخواست محصولات و عکس عمومی `/api/supabase/...` را با علت Googlebot blocked by robots.txt نشان داد. قانون کلی Disallow: /api/ موجب مسدودشدن منابع لازم برای رندر می‌شد؛ خطای خواندن محصول در React هم عمداً noindex نشان می‌دهد. این شاهد، مانع فعلیِ نمونهٔ فعال را اثبات می‌کند؛ علت زمان‌بندیِ خزش تمام آدرس‌های قدیمی از آن نتیجه گرفته نمی‌شود.

## اصلاح

- robots.txt برای منابع عمومی محصولات، دسته‌ها، تصاویر، تنوع‌ها و فایل‌های عمومی سطل product-images استثنا دارد. مسیر نام جدول دقیق است و جدول‌های هم‌نام مانند products_archive یا زیرمسیر دیگر را مجاز نمی‌کند.
- محدودیت کلی API، مسیرهای احراز هویت، دادهٔ مشتری، RPC، فایل‌های امضاشده و فایل‌های مرجوعی باقی است. robots.txt کنترل دسترسی نیست؛ مجوزها، RLS و کد API تغییر نکرده‌اند.
- صفحات حساب، ورود و پرداخت برای دیدن noindex قابل خزش‌اند؛ noindex آن‌ها و وضعیت ۴۰۴/۵۰۳ محصول حذف‌شده/خطای سرور تغییری ندارد.
- ابزار check-site-seo اکنون علاوه بر HTML اولیه، امکان خزش منابع عمومی و حفظ محدودیت APIهای خصوصی را ارزیابی می‌کند. بررسی قبلی فقط ممنوع‌نبودن ریشه را می‌سنجید و این خطا را تشخیص نمی‌داد.
- اعتبارسنج، قالب کنترل‌شدهٔ همین پروژه با گروه یکنواخت User-agent: *، مسیرهای literal و علامت پایانی $ را می‌پذیرد؛ parser عمومی همهٔ قالب‌های robots.txt نیست. گروه اختصاصی ربات یا wildcard پشتیبانی‌نشده با robots_policy رد می‌شود.

## آزمون و پذیرش

آزمون رگرسیون مرورگر با کاتالوگ ساختگی و بدون اتصال زنده، قانون قبلی را به شکست رندر/noindex و قانون فعلی را به نمایش محصول، canonical و تصویر بارگیری‌شده تطبیق می‌دهد. تست سیاست، نام جدول‌های مشابه و APIهای خصوصی را هم بررسی می‌کند. نتایج اجرای نهایی در گزارش کار ثبت می‌شوند.

پس از انتشار، در Search Console باید Test live URL همان محصول دوباره اجرا شود؛ انتظار Crawl allowed=Yes، Page fetch=Successful و Indexing allowed=Yes است. پس از دریافت سیاست تازه توسط گوگل، تصاویر و درخواست محصول نباید blocked by robots.txt باشند. زمان خواندن مجدد robots یا ایندکس‌شدن تضمین نمی‌شود. خطای مستقل تصویر اینماد، شاهد این باگ نیست و در این اصلاح تغییر نمی‌کند.

این تغییر به‌خودی‌خود دیپلوی، ارسال درخواست ایندکس یا Validate fix انجام نمی‌دهد. منابع: [رندر JavaScript در گوگل](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)، [تفسیر robots.txt](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec).
